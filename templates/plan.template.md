## 6. 不改清单（Do-Not-Touch，Coding Agent 硬约束）

列出交给 Coding Agent 编码时，**不允许它自行改动**的东西——本组所有硬约束都归到这一节，别处不重复列，例如：

- spec.md §5 的验收标准（US-01…）文字
- prd.md §7 的 Golden Path 对话原文（可以改实现，不能改这段对话期望产生的效果）
- 已选定的需求分类范围（spec.md §3）
- 工作坊统一约定的东西（评测脚本、端口约定等，如果有）

**Agent 起草时必须附上盲区清单**（这一节漏一条，编码阶段就少一道防线，而漏掉的那条不会以任何形式显示在文件里——人评审时主要审这张表）：

| 我不确定该不该锁的东西 | 锁了的代价 / 不锁的风险 | 人裁决 |
|---|---|---|
| 例：mock 数据里的订单号 3426436 | 锁死则 Agent 不能改测试数据；不锁则它可能顺手换掉，Golden Path 演示就对不上了 | ⬜ 锁 / ⬜ 不锁 |
| 例：三栏 UI 的布局结构 | 锁死则样式没法优化；不锁则可能被重构成单栏，"执行流程可见"这条验收就没了 | ⬜ 锁 / ⬜ 不锁 |
